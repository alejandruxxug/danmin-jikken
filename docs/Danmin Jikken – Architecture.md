## 🧑‍🏫 OOP in Go: how each concept shows up in the game

Go has **no classes and no inheritance**. "OOP in Go" means structs, methods, interfaces and embedding. Every concept below should be something Alejo can point at in the demo.

| OOP concept | Go mechanism | In Danmin Jikken |
|---|---|---|
| **Encapsulation** | Unexported fields + methods, `NewX()` constructors | `Patient` hides its sleep state; only `Nudge()` and `IsAsleep()` touch it |
| **Abstraction** | Interfaces | `Scene` (`Update`, `Draw`), `Document` (`Check(rules) []Discrepancy`) |
| **Polymorphism** | Interface values | The desk handles SettlerID, Referral, SleepLog and Wristband through one `Document` list |
| **Composition over inheritance** | Struct embedding | A `Patient` embeds `Sleeper` and `Person`. The trial patients embed a different `Sleeper` (the twist is literally a different type) |
| **Interface segregation** | Small interfaces | `Sleeper` is just `Sleep()` / `Wake()` / `Asleep() bool` |

## 💤 The sleepy patients = goroutines

Each patient runs a goroutine with a random sleep timer:

```go
// sketch, not final
func (s *narcolepticSleeper) run(ctx context.Context, events chan<- SleepEvent) {
    for {
        select {
        case <-ctx.Done():
            return
        case <-time.After(s.nextAttack()): // random interval
            events <- SleepEvent{ID: s.id, Asleep: true, At: s.clock.Now()}
        }
    }
}
```

**Rule that matters:** Ebitengine's `Update`/`Draw` run on one thread. **Goroutines never touch game state directly.** They send events on a channel, and the `Ward` drains the channel inside `Update`. That avoids data races and is a good line for the sustentación.

- `context.Context` stops a patient's goroutine when they're discharged or the scene ends.
- The **game clock** is injected, so the 3:17 AM in-game time is controllable (and testable).
- The **ward monitor** (night) draws one line per live goroutine. That's the debug view and a story beat at once.

## 🤖 Agent backdoor (test mode)

Alejo, 2026-10-13: the game has a **backdoor so a Claude agent can go exactly where it needs to** and testing is easy. It's a set of command-line flags, **off unless `-agent` is passed**. Same idea as a cheat menu. All of it lives in **one file, `game/agent.go`**, in plain Go (Alejo has to defend it), and it only calls things the game already has (SceneManager, Ward, clock). It never touches `hospital/`.

```bash
cd game
go run ./cmd/danmin -agent -scene day.reception -day 2 -clock 15:40 -seed 7 \
    -input ../testdata/admit_two.txt -shot /tmp/out.png -dump /tmp/state.json -quit
```

| Flag | Does | Why the agent needs it |
|---|---|---|
| `-agent` | Turns test mode on. Without it every other flag below is ignored | Players can't trip it |
| `-scene <id>` | Starts straight in that scene (ids in the table below) | No playing from the title to reach day 3 |
| `-day N`, `-clock HH:MM` | Sets the day and in-game time (the clock is injected already) | Day 3 / 3:17 AM on demand |
| `-seed N` | Fixes the random seed: same patients, same order, every run | Screenshots are comparable between runs |
| `-flags a,b` | Pre-sets story flags (choices carried day → night) | Test any night branch directly |
| `-speed N` | Game time ×N | Watch a whole shift in seconds |
| `-input <file>` | Plays a script of inputs (below) | Clicks and keys without a human |
| `-shot <file.png>` | Saves a screenshot at **1× (480×270)**, plus `-shot4` at ×4 to compare with the Figma view | The agent *sees* the screen |
| `-dump <file.json>` | Writes the game state: scene, day, clock, patients (state, room), rooms, scores, flags | Check logic, not only pixels |
| `-quit` | Exits after the input script ends (or after `-frames N`) | Runs inside a test command |

**Input script** (one command per line, `#` = comment):

```
wait 30            # frames
key Space
click 212 140      # 1× game coordinates (Figma px ÷ 4)
shot after_admit.png
dump after_admit.json
```
